# ETF 모멘텀 프로젝트 보완 제안

작성일: 2026-10-07

## 목적과 적용 범위

이 문서는 대화에서 제안한 여섯 가지 보완 사항을 구체적인 작업과 완료 기준으로 정리한다. 현재 README와 CLAUDE.md의 프로젝트 목적은 **연금 계좌 등에서 보유할 모멘텀 ETF를 고르는 것**이다. 실제 투자 비중, 핵심·보조 비율 및 주문은 사용자가 결정한다.

따라서 선정 정확성·데이터·검증·월간 기록은 현재 도구의 우선 보완 대상이다. 앞서 제안한 목표 비중과 주문 변경표도 아래에 보존하되, 이는 사용자가 범위를 넓힐 때의 선택적 확장이다. 현재 도구에 자동매매나 통합 계좌 한도 기능이 반드시 필요하다는 뜻은 아니다.

## 1. 기본 전략을 설정 파일로 고정한다

문제: CLI 옵션을 매번 입력하면 rank, backtest, weekly가 서로 다른 규칙으로 실행되기 쉽다. 일부 JSON은 portfolio 전용이며 ETF 선정 규칙 전체를 고정하는 공통 전략 파일은 없다.

작업:

- 유니버스, 계좌 유형, benchmark/cash, lookbacks·skip·점수 가중치, SMA, 순위 기준, 유동성, top_n 및 그룹 제한을 하나의 전략 설정으로 관리한다.
- 설정에 전략 ID·버전·적용 시작일을 둔다. 연구용 변경 설정과 현재 관찰용 설정을 구분한다.
- rank/backtest/weekly에서 같은 설정을 읽고, CLI override가 있으면 적용 후 전체 설정과 해시를 기록한다.
- 파라미터 변경 시 기존 관찰 기록을 덮어쓰지 않는다. 설정 변경을 매달의 ETF 교체와 구분한다.

완료 기준: 같은 가격·거래대금·기준일·설정으로 rank의 월말 선정과 backtest의 해당 월말 선정이 일치하고, 각 출력에 같은 전략 해시가 남는다.

## 2. 선정 결과의 이유와 판단 기준을 함께 출력한다

현재 목적에 맞는 작업:

| 출력 | 구체적인 내용 |
|---|---|
| 선택 종목 | 순서, 티커, 이름, 그룹, 계좌 적격 여부 |
| 편입 근거 | 모멘텀 점수·순위, SMA 대비 값, 당시 평균 거래대금 |
| 제외 근거 | 모멘텀·추세·유동성·변동성 계산·그룹 제한 중 실제 탈락 이유 |
| 현금 대기 이유 | 시장 필터 꺼짐인지 적격 후보 부족인지 명시 |
| 기준 정보 | 신호일, 실행일, 원자료의 종목별 마지막 관측일, 전략 버전 |

현재 latest_selection.csv는 selected/group_limit/cash와 risk_on을 제공한다. 여기에 당시 지표와 상세 이유를 연결하면, 최신 랭킹과 월말 선택이 다른 이유도 설명할 수 있다. SMA 설명에는 실제 설정값을 사용한다.

선택적 확장: 목표 비중을 출력하려면 비중 방식·개별 상한·변동성 목표·계좌 상한까지 백테스트와 같은 배분 함수를 공유해야 한다. 현재 선정 전용 출력에 임의의 동일 비중을 붙이면 다른 비중 방식의 연구 결과와 혼동된다.

완료 기준: CSV만 읽어도 언제 어떤 규칙으로 선정했고 왜 현금 슬롯이 생겼는지 설명할 수 있다. 출력은 당시 신호를 기반으로 하며 이후 가격을 사용하지 않는다.

## 3. 현재 보유와의 변경 내역을 제공한다

현재 목적에 맞는 최소 작업: 사용자가 보유 티커를 입력하면 유지·신규 편입·선정 제외를 구분한다. 수량·주문금액 없이도 ETF 교체 판단에 도움이 된다.

선택적 확장: 수량·현금·사용자가 정한 목표 비중을 입력받아 매수/매도 수량, 예상 거래금액, 비용과 잔여 현금을 계산한다. 정수 수량, 거래단위와 주문 규모 대비 거래대금을 반영한다. 사용자가 검토하는 실행안으로 출력한다.

완료 기준: 최소 기능에서는 기존 보유와 선정 목록의 차집합이 정확하다. 수량 기능을 추가할 경우 매수 대금·비용이 가용 현금을 넘지 않고, 임의 비중이나 자동 주문을 도입하지 않는다.

## 4. 관찰 후 실제 실행 시점과 백테스트 가정을 맞춰 검증한다

문제: 기본 백테스트는 월말 종가로 신호와 체결을 동시에 가정하지만, README의 사용 흐름은 월초 주말에 확인하는 것이다. 같은 종가 체결 결과만으로 그 사용 흐름의 성과를 설명하기 어렵다.

작업:

- 같은 종가 체결과 다음 거래일 종가 체결을 구분하는 execution 옵션을 제공한다. OHLC를 확보하면 다음 시가도 비교한다.
- 월초 주말 확인 흐름을 유지한다면, 확인 이후 첫 가능한 거래일을 별도 실행 시나리오로 평가한다.
- 거래비용을 여러 수준으로 바꾸고, turnover·최악 구간과 함께 비교한다.
- 외국 가격·환율의 관측 시점과 한국 거래일 매핑을 기록한다.

완료 기준: 다음날 체결 모델에서 체결 이전 수익을 얻지 않고 기존 보유 수익은 체결까지 반영한다. 비교 결과에 신호 시점·체결 방식·비용이 남는다. 체결 지연과 비용을 바꿨을 때 결론이 유지되는지 확인한다.

## 5. 전략의 역할에 맞는 성과 평가를 추가한다

모멘텀 단독과 다른 자산에 섞은 포트폴리오는 별도 질문이다. 단독에서는 선정 규칙이 벤치마크보다 어떤 장단점이 있는지, 조합에서는 낙폭·회복·회전율에 어떻게 기여하는지 본다.

작업:

- CAGR·Sharpe·MDD에 최악의 12개월 수익률, 고점 회복 기간, 연간 회전율, 현금 비중을 추가한다.
- 비교마다 통화·기간·달력·현금 수익률·거래비용을 맞춘다.
- 학습 선택의 Sharpe와 보고용 Sharpe를 같은 정의로 계산한다.
- 고정 설정, 워크포워드 선택, 사후 최고 조합을 명확히 구분한다. 데이터·유니버스·설정의 사후 선택은 별도 한계로 남긴다.
- 연구 표를 저장 결과에서 생성하는 스크립트와 정확한 입력 목록을 유지한다.

완료 기준: 단일 슬리브 포트폴리오와 원 전략의 성과 지표가 같은 평가 기준에서 일치한다. 같은 평가 기간에 대해 보고 비용 합계와 리밸런싱 기록이 맞는다. 데이터 누락을 수익률 0으로 숨기지 않는다.

## 6. 월말 신호를 모의 운용 기록으로 축적한다

작업:

- 월말 신호마다 전략 버전, 당시 입력 파일 해시, 가격·거래대금 관측일, 선택·탈락 이유와 종목을 보존한다.
- 실행 기록과 신호 기준일을 구분한다. 이미 저장한 신호는 재조회한 데이터로 덮어쓰지 않는다.
- 이후 성과를 해당 당시 선정 목록으로 평가한다. 데이터 수정으로 재계산한 결과는 별도 revision으로 기록한다.
- weekly 기록도 시장·유니버스·계좌·전략 설정별로 분리한다.

완료 기준: 당시 관측 기록으로 월말 선택을 재현할 수 있고, 전략 변경 전후의 기록이 섞이지 않는다. 새 데이터를 받아도 과거의 의사결정 기록이 보존된다.

## 작업 순서

1. 시장 필터 및 종목별 가격의 누락·신선도 검증, 월말 기준일 검증.
2. 선정 전략 설정 고정 및 상세 선정 이유 출력.
3. 월간 신호 보존과 weekly 기록의 전략별 분리.
4. 체결 지연·비용·학습 지표의 검증과 연구 표 재현.
5. 보유 티커 대비 변경표.
6. 사용자가 운용 보조 범위를 확장하면 목표 비중·주문 수량 기능을 추가.

현재 구현의 실측 리뷰는 `docs/review_concept_2026-10-07_codex.md`에 별도로 기록했다. 이 문서는 개선 제안이며 기능 구현을 완료했다는 보고가 아니다.
