## 역할과 전달물

| 담당 | 책임 | 수정 권한 | 전달물 |
|---|---|---|---|
| GPT/Codex | 요구사항·설계·완료 기준, Orca 진행 관리, 발견사항 판단·최종 보고 | 작업 설계/최종 보고 문서 | task, design, final |
| Claude | 합의한 범위의 구현·필요한 회귀 테스트, 검증 실패 수정 | 해당 단계에서 지정한 제품 코드·테스트·관련 설명 | implementation, 변경 목록, 실행 로그 |
| Gemini | 요구사항 대조, 독립 수식·경계 조건·회귀 검증 | 검증 문서와 임시 재현 자료 | verification, 재현 코드·명령 |

한 시점의 제품 코드 편집자는 Claude 한 명으로 둔다. 검증 중에는 대상 소스를 고정한다. Gemini의 발견사항은 GPT가 증거를 확인하고 Claude에게 수정 작업으로 전달한다. Gemini는 제품 코드를 직접 고치지 않는다.

## 한 작업의 순서

1. **GPT 설계:** `CLAUDE.md`, 관련 요구사항, 현재 코드와 상태를 읽고 작업 범위·불변 조건·완료 기준을 작성한다. 변경이 필요 없을 수도 있는 검증 작업은 그 가능성을 명시한다.
2. **Claude 구현:** 설계를 읽고 현재 동작을 재현한다. 필요한 변경과 회귀 테스트를 만들고 변경 목록·실행 결과를 남긴다. 이미 해결된 항목을 다시 수정하지 않는다.
3. **검증 대상 고정:** 저장소 경로, HEAD, 작업 트리 상태, diff 및 필요하면 미추적 소스/입력 파일 해시를 기록한다. HEAD만으로 미커밋 작업을 식별했다고 주장하지 않는다. 검증 도중 코드가 바뀌면 같은 검증 결과로 승인하지 않는다.
4. **Gemini 독립 검증:** 요구사항·대상 리비전/스냅샷·입력·완료 기준으로 먼저 검증한다. 첫 판단을 내리기 전 Claude의 성공 결론이나 예상 정답은 전달하지 않는다. 독립 검증 후 구현 설명과 교차 대조한다.
5. **수정 반복:** Gemini의 실패 항목을 재현 가능한 형태로 Claude에게 전달한다. 변경 후 관련 검증과 필요한 공통 회귀 검증을 다시 한다. 같은 실패가 반복되면 GPT가 원인을 정리해 설계를 보완한다.
6. **GPT 완료 보고:** 완료 기준별 통과·실패·미검증, 실제 코드 변경, 테스트 결과, 제한을 보고한다. 자료 부재는 통과로 취급하지 않는다.

## 공통 제약

- `CLAUDE.md`는 세 모델이 모두 읽는다. 목적은 ETF 선정이며, 새 주문·통합 배분 기능은 이번 흐름의 필수 요구사항이 아니다.
- 리뷰 단계에는 `.agents/skills/etf-momentum-code-review/SKILL.md`와 체크리스트를 읽고 적용한다. Orca의 검증 담당 한 명을 독립 리뷰어로 사용하고 별도 리뷰어를 중복 생성하지 않는다.
- 과거 리뷰 문서의 결론은 현재 코드로 재현한다. 계산 기대값은 독립 수식으로 만든다.
- 원자료·운영 캐시·signals/weekly 이력·기존 연구 결과는 보존한다. 실험 출력과 캐시는 작업별 임시 디렉터리에 둔다.
- 테스트는 먼저 관련 범위, 공통 선정·데이터·회계가 바뀌면 전체 범위로 실행한다. 실행하지 않은 테스트를 통과로 기록하지 않는다.
- 공식 연구 결과 생성에는 `CLAUDE.md`의 코드 커밋·clean 상태·고정 종료일 규칙을 적용한다. 미커밋 상태 검증은 리뷰 실험으로 표시한다. 이 절차 자체가 커밋·푸시·운영 결과 재생성을 지시하지 않는다.
- 실제 주입된 Orca worker 지시의 Run/Task/Dispatch 정보와 완료 보고 절차를 따른다. 문서에서 임의 ID나 lifecycle 명령을 만들어 실행하지 않는다.

## 기록 위치

공유 작업 문서는 작업별로 `docs/workflows/<작업-ID>/`에 남길 수 있다. 공식 연구 결과 생성 중에는 새 문서를 추가하지 않고 임시 경로에 기록한 뒤 결과 생성 종료 후 옮긴다.


각 단계가 다음 담당자에게 넘길 때는 절대 저장소 경로, 입력 문서 경로, 소스 스냅샷, 허용 수정 범위, 구체적인 산출물과 완료 증거를 포함한다. 임시 경로를 사용할 경우 세 세션에서 같은 파일을 읽을 수 있는지 확인한다.

## Orca 진행 관리

사용자가 위 시작 작업을 요청한 뒤 GPT 조정 세션에서 버전에 맞는 `orca skills get orchestration --json` 지침을 읽고 진행한다. 기존 세션 재사용 시 현재 대화 맥락과 다른 진행 작업을 확인한다. 재사용에 적합하지 않으면 새 역할 전용 세션을 사용한다.

Run은 작업 기록과 조정 inbox이며 자동 스케줄러는 아니다. 조정자가 단계의 의존성을 확인하고 준비된 작업을 배정한 다음 완료 보고를 처리한다. 메시지를 보냈다는 수신증과 작업 시작/완료를 구분한다. 검증 실패는 내용상 실패로 명시하고, 세션 침묵을 실패로 단정해 중복 편집자를 실행하지 않는다.

완료된 worker는 Orca 지침에 따라 다음 작업에 재사용하거나 명시적인 유지/해제 결정을 한다. 사용 중이던 세션을 무작정 종료하지 않는다. 흐름 종료 시 각 작업의 결과와 남은 세션 처리 상태를 보고한다.
