# 원자료 관측 보존과 거래소 달력 설계

작성일: 2026-10-09
관련: `docs/review_2026-10-08_codex.md` 1·2·4번

## 목적

- 가격이 **실제로 관측된 날**을 잃지 않는다. 지금은 캐시에 앞 값으로 채운 가격을 저장해, 데이터 누락과 실제로 가격이 그대로인 날을 구분할 수 없다.
- 시장 필터·현금 ETF·후보 ETF의 **최신성**을 실제 관측일로 판단한다.
- 직전 월말을 **거래소 달력의 실제 마지막 거래일**로 정하고, 그날 데이터가 없으면 멈춘다.

ETF 선정의 정확성을 위한 변경이며, 투자 비중·주문 기능은 다루지 않는다.

## 1. 원자료 캐시와 관측표

### 캐시

- 가격 다운로드는 **앞 값으로 채우지 않은 종가**를 캐시한다. 파일 이름 접두어는 `prices_raw_`. 모든 값이 빈 열과 행만 지운다.
- 기존 `prices_*` 캐시는 읽지도 지우지도 않는다(새 이름이라 자연히 다시 받는다).
- 거래대금 캐시(`traded_value_*`)는 이미 채우지 않고 저장하므로 바꾸지 않는다.

### 함수

- `download_prices(tickers, start, end, cache_dir, refresh, max_age_hours, raw=False)`
  - `raw=False`(기본): 지금처럼 앞 값으로 채운 가격을 돌려준다. 계산 코드는 그대로 쓴다.
  - `raw=True`: 채우지 않은 원자료를 돌려준다. 같은 캐시를 쓰므로 추가 다운로드가 없다.
- 관측표: `observed = download_prices(..., raw=True).notna()` (날짜×티커의 참/거짓).
- 상장 전 기간을 프록시로 채운 경우(`--use-proxies`), 채운 날은 관측된 것으로 본다(프록시가 그날 관측됐으므로).

## 2. 최신성 판단

공통 규칙: **판단일 기준으로 마지막 관측 이후 지난 거래일이 5일(`PRICE_MAX_STALE_DAYS`)을 넘으면 오래된 데이터**다. 거래일은 가격표의 날짜 행으로 센다. (2026-10-13 변경: 행 수와 거래소 거래일 수 중 큰 쪽으로 센다. 모든 티커가 빠진 날은 행이 없어 행 수만으로는 공백이 줄어들기 때문이다. `docs/review_2026-10-13_full_codex.md` G01)

| 대상 | 판단 시점 | 오래됐을 때 |
|---|---|---|
| 후보 ETF | 각 순위 계산일 | `price_fresh=False`, 후보에서 제외. `last_observed` 컬럼 추가 |
| 시장 필터 티커 | 각 선택일 (`select_holdings`) | **오류로 멈춤** (투자 상태로 넘어가지 않음) |
| 벤치마크·시장 필터·현금 ETF | 실행 전, 가격 데이터의 마지막 날 기준 | **오류로 멈춤** |

- 관측표를 넘기지 않는 라이브러리 호출(기존 테스트, 연구용 직접 호출)은 지금의 "가격이 5거래일 넘게 그대로" 규칙을 대신 쓴다.
- 관측표가 있으면 실제로 가격이 그대로인 날(관측은 있음)은 오래된 것으로 보지 않는다.

## 3. 거래소 달력으로 직전 월말 판단

- 의존성 추가: `exchange_calendars` (KRX `XKRX`, NYSE `XNYS` 거래일을 안다).
- 거래소 선택: 벤치마크가 `.KS`/`.KQ`로 끝나면 `XKRX`, 아니면 `XNYS`.
- `previous_month_end(dates, today=None, sessions=None)`:
  - 대상 달: `today`가 속한 달의 바로 전 달(지금과 같음).
  - `sessions`(거래소 거래일 목록)를 주면: 대상 달의 마지막 거래일이 월말이다. **그 날짜가 `dates`에 없으면 멈춘다**("9월 마지막 거래일 2026-09-30 데이터가 없습니다").
  - `sessions`가 없으면 지금 규칙(마지막 평일 또는 다음 달 데이터)을 쓴다.
- CLI의 `dates`는 **벤치마크의 실제 관측일**이다. 여러 티커를 합친 날짜가 아니다.
- 달력 범위 밖(예: 달력이 아직 모르는 미래)이면 지금 규칙으로 대신하고 그 사실을 출력한다.

## 4. 포트폴리오 명령

- `calendar_ticker`와 `same_day` 슬리브(티커)는 **원자료**로 만든다. 원자료에 빈 날이 있으면 기존 규칙대로 공백 오류로 멈춘다(리뷰 4번 재현 경로).
- `previous_close` 슬리브와 환율은 지금처럼 이전 관측 값을 쓴다.

## 5. 연구 데이터 영향

- 캐시가 바뀌므로 기간을 고정한 연구 데이터(`--end 2026-10-07`)도 한 번 새로 받는다.
- 연구 문서가 쓰는 결과(워크포워드 10개, 고정 설정, 체결 시점 비교, 조합, 표)를 모두 다시 만들고, **이전 수치와 비교표**를 남긴다. 야후가 과거 가격을 고쳤다면 수치가 조금 바뀔 수 있다.
- 바뀐 수치는 연구 문서에 반영하고, 변경 이유(원자료 재다운로드)를 적는다.

## 6. 테스트

| 영역 | 확인할 것 |
|---|---|
| 원자료 | 원 종가 `[100, NaN, 110, 111]`이 `raw=True`에서 NaN으로 남고, 기본값에서는 채워짐. 캐시 파일에 NaN이 그대로 저장됨 |
| 후보 최신성 | 관측표에서 60거래일 미관측 → 제외. 실제로 가격이 6일 이상 같지만 관측됨 → 포함 |
| 시장 필터 | 관측 기준 오래된 필터 → 오류. OR 필터 중 하나만 오래돼도 오류 |
| 실행 전 검사 | 벤치마크·현금 ETF가 마지막 날 기준 오래됨 → 멈춤 |
| 프록시 | 프록시로 채운 상장 전 기간은 관측으로 처리 |
| 월말 | 9/15 + 10/01 데이터 → 멈춤(리뷰 재현), 연말 휴장(12/30), 추석(2023-09-27), 정상 월말, 달력 없을 때 기존 규칙 |
| 포트폴리오 | 원자료 내부 NaN이 있는 티커 슬리브 → 공백 오류 |
| 기존 동작 | 기존 테스트 전부 통과(관측표 없이 부르는 경로 포함) |

## 범위 밖

- 거래대금 캐시 형식 변경(이미 원자료).
- 신호 기록에 입력 데이터 스냅샷 저장(리뷰의 설계 한계 항목, 별도 과제).
- 기존 `prices_*` 캐시 파일 삭제(정리 작업은 사용자 확인 후 별도).
