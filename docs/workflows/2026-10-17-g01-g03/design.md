# 진행 설계

## 단계

1. GPT가 시작 리비전과 작업 트리/해시, 요구사항, 역할을 고정한다.
2. Claude 전용 Orca worker가 현재 구현을 확인한다. 필요한 경우만 수정하고 관련 테스트·전체 회귀 결과 및 구현 보고서를 남긴다.
3. GPT가 Claude 완료와 소스 변경 목록을 확인한다. 제품 코드·테스트·설정·README/CLAUDE 등 검증 대상 지문을 저장하고 편집을 동결한다.
4. Gemini 전용 Orca worker가 `task.md`, 요구사항 문서, 고정 소스 지문으로 독립 검증한다. 첫 판단 전 `implementation.md`와 Claude 완료 보고를 읽지 않는다. 제품 변경 권한은 없다.
5. GPT는 독립 보고와 구현 보고를 교차 대조한다. 실패를 재현하고 필요한 수정을 Claude에게 배정한다. 새로운 소스 지문으로 Gemini 재검증을 받는다.
6. GPT가 완료 기준별 결과·변경·제한·Orca 작업과 세션 처리 상태를 `final.md`에 기록한다.

이 순서는 같은 파일에 대한 동시 편집과 검증 대상 이동을 막는다. Run은 진행 기록이며 각 단계의 실제 시작/완료를 조정자가 확인한다. 사용자 기존 세션의 대화가 길거나 별도 작업이 진행 중이면 해당 모델의 기본 설정을 따르는 새 worker 세션을 사용한다.

## 구현 검토의 기대 범위

G01은 `observed_freshness`와 rank/select/실행 전 필수 검사까지의 세션 전달을 추적한다. 가격표 행 수와 거래소 세션 수의 큰 값을 쓰는 정책, 평가일 이후 관측을 참조하지 않는 조건, 달력 없는 호출의 fallback을 확인한다.

G02는 고정 캐시 누락 목록 → `.retry` 다운로드 → 네이버 보완 → 완료 여부 → 원 캐시 합치기 → 재시도 상태 갱신을 따라간다. 실패한 다운로드가 DataFrame을 반환할 수 있는 경계와 이전 retry 파일을 구분해야 한다.

독립 검증은 위 요구사항에 대한 새 작은 입력과 직접 수식으로 수행한다. 기존 회귀 테스트만 통과한 사실과 독립 재현 결과는 별도 증거로 기록한다. 구현 결과를 기대값으로 다시 사용하지 않는다.

## 완료 판정

관련 회귀·독립 계산·경계 검증과 전체 테스트가 통과하고 소스 스냅샷이 검증 동안 유지되면 해당 범위를 통과로 판정한다. 입력 자료 부재와 외부 시세 미대조는 별도 제한이다. 공식 결과를 생성하지 않으므로 dirty 상태를 숨기거나 커밋해 없애지 않는다.
